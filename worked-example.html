What a Freight Invoice Audit Returns: One Document, End to End

Most invoice-automation demos show you a PDF and a JSON blob. That tells a bookkeeper nothing about whether the output can go into a close.

This post shows the whole path for one document: every field extracted, every arithmetic check run, and every item that still needs a human. The document is a sample LTL freight invoice, ANF-INV-2026-004918, two pages, USD 1,886.50, 40 extracted fields. It is an illustrative sample, not a client invoice, and it is labelled that way throughout.

Who this is for

Primary buyer: bookkeeping and accounting firms serving ecommerce sellers. You receive supplier and freight documents from clients, and someone has to turn them into rows that reconcile. This is that step, with the exception list attached instead of hidden.

Second buyer: shippers, 3PLs and freight brokers. The same output drives overcharge recovery: fuel surcharge percentage, accessorial validation, rate-per-pound comparison against a carrier rate card. The workflow is identical; the questions asked of the numbers are different. The two offers are priced and sold separately.

4. Exceptions: what still needs a human

  1. NMFC item 123456. Six digits with no sub-class. Class 70 is plausible, but the item number has to be checked against the carrier tariff before the classification is relied on.
  2. Declared value USD 75,000 with no declared-value charge line. Either the charge was waived or the coverage is not actually in place. Worth one question before the invoice is approved.
  3. Carrier authority, MC-987654 and USDOT 3124567. Not verified in this sample. Verification against the FMCSA register is a separate step.
  4. Tax stated as non-taxable, USD 0.00, with no jurisdiction shown. Freight taxability varies by state and by service. The address on the invoice is not proof of the tax treatment.
  5. Bank account masked as *4921.** The routing number passes its checksum; the account cannot be verified from the document, so payment detail needs a second source.
  6. Page footer reads "Page 1 of 1" on a two-page document. One line, but it is the kind of error that later argues about whether a page is missing.

6. What you receive per packet

A packet is one freight invoice with its supporting transport documents, not one PDF file.

  • extraction.json, one record per document, field level, with page references
  • extraction.csv, the same rows for the accounting import
  • exceptions.md, every item that needs a human, with the reason
  • reconciliation.md, the arithmetic and the derived measures
  • One audit note stating which checks ran and which did not

7. Data handling

  • Documents are processed for the run and returned as output files.
  • Extracted text and outputs are written to the client's own folder, not to a shared pool.
  • No document content is used to train a model.
  • Retention is stated per engagement, and deletion is a written instruction, not a setting someone has to remember.

9. What this example does not prove

  • It does not prove a field accuracy rate. One document is a demonstration, not a measurement.
  • It does not prove handling of scanned or photographed invoices. This one has a text layer.
  • It does not prove multi-carrier rate-card comparison. No rate card was supplied.
  • It does not prove that a bookkeeping firm will pay for it. That is a customer question, not a document question.

Each of those is a separate test, and I would rather name them than imply them.
